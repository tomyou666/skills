# Qiita Writing Principles

## いつこのスキルを使うか

- Qiitaで**これから記事を書こうとしているとき**に、「どう構成すれば刺さるか」を整理したいとき。
- すでに書いた草稿を「**いいねが付きやすい型に寄せてブラッシュアップ**」したいとき。
- 「ポエム寄り」「体験談ベース」だけど、**再現性のある学びやフレームを入れたい**とき。

このスキルは、以下2本のQiita記事から共通パターンを抽出してまとめている：

- 「エンジニアが『事業を動かせる人』になるための4要素」
- 「Claude Code × Obsidianで実現！Qiita記事執筆を完全自動化した話」

## サンプル記事から抽出したパターン

### 1. 想定読者と「この記事でわかること」を先に出す

**パターン**

- 冒頭に「想定読者」と「この記事でわかること」を明示する。
- 読者が「自分向けの記事か」「読む価値があるか」を**10秒以内に判断できる**状態にする。

**チェックポイント**

- 想定読者が **属性×状態** まで言語化されているか？
  - 例: 「技術力だけでキャリアを築くことに限界を感じ始めたエンジニア」
- 「この記事でわかること」が **箇条書き 3〜5個** で具体的に書かれているか？
  - 例: 「事業を動かせるエンジニアの4要素」「今日からできる具体的な一歩」

### 2. 個人的な原体験・感情から始める

**パターン**

- 「正直に書きます」「僕は記事を書くのが苦手でした」など、**自分の弱さや違和感から始める**。
- 事実だけでなく、「焦り・違和感・モヤモヤ」などの**感情を1〜2文で明示**する。
- 「できる人の成功談」ではなく、「目指している途中の人の思考ログ」として書くことで、読者との距離を縮める。

**チェックポイント**

- 冒頭に「ある時、〜と強く感じました」「正直、〜が苦手でした」などの**一人称の感情文**が入っているか？
- 「できる人の話」ではなく「自分はまだ道半ば」という立ち位置が伝わる一文があるか？

### 3. ロールモデルやゴール像を先に置く

**パターン**

- 「こんな先輩がいた」「こういう状態になりたい」という**ロールモデル/ゴール像**を早めに提示する。
- そのロールモデルを**要素分解して構造化**する（4要素ツリーなど）。

**チェックポイント**

- 「この人のようになりたい」「この状態を目指したい」が1つ具体例で書かれているか？
- その理想像を3〜5個の要素に分解した図や箇条書きがあるか？

### 4. 抽象を「方程式」「フレームワーク」にする

**パターン**

- `市場価値 = 希少性 × 需要` のように、**1行の方程式・フレーム**でまとめる。
- 長い議論の途中に「図・ツリー・表・箇条書き」を挟んで、**読み手の理解をリセット**する。

**チェックポイント**

- 記事の中心となる「式」や「図」が1つ定義されているか？
- 長い文章だけでなく、**構造を一目で理解できるブロック**が含まれているか？

### 5. 「なぜこの順番か」をきちんと説明する

**パターン**

- 単に要素を列挙するのではなく、「**どの順番で学ぶ/実行するか**」とその理由を書く。
- 順番の説明自体が1つの学びになるようにする。

**チェックポイント**

- 「全部同時にやろうとすると挫折します」「この順番が一番コスパが良い」などの説明があるか？
- 各ステップの前提関係が言語化されているか？

### 6. 今日からできる具体的な一歩を必ず入れる

**パターン**

- 記事の後半で「今日からできる具体的な第一歩」を提示する。
- 所要時間（3時間、30分、5分など）を書き、**読者がやるイメージを持てるようにする**。

**チェックポイント**

- 「今日からできる」「今週やってみてほしい」などの見出しがあるか？
- 各アクションにおおよその所要時間が書かれているか？

### 7. Before/After・効果をストーリーで示す

**パターン**

- 自分のBefore/Afterを、「時間」「ストレス」「成果」などで描写する。
- 「予想以上に快適」「執筆時間が半分以下になった」のように、**変化を定量/定性で示す**。

**チェックポイント**

- 「Before:」「After:」のように切り分けた説明がどこかにあるか？
- 変化を示す具体例（時間、回数、感情の変化など）が1つ以上入っているか？

### 8. 仕組み・構成図で「全体像」を見せる

**パターン**

- システム図やディレクトリ構成、フロー図などで**全体像を最初に示す**。
- 読者が「この仕組みはこう繋がっているのか」を早めに掴めるようにする。

**チェックポイント**

- コードや詳細説明の前に、**簡単な全体図・構成図**が提示されているか？
- 図のあとに、「このシステムは◯個の○○で構成されています」のようなまとめがあるか？

### 9. メタ視点・実戦投入の話を入れる

**パターン**

- 「この記事もこのシステムで書いています」のように、**自分自身で使った記録**を書く。
- 実戦投入中に発生した改善サイクル（その場で機能追加した話など）を入れる。

**チェックポイント**

- 「実際に使ってみた感想」「この記事自体も〜」などの**メタな一文**があるか？
- 使いながら改善したエピソードが含まれているか？

### 10. 「技術スタック」「セットアップ手順」で再現性を担保する

**パターン**

- 技術スタック一覧・MCP連携・ディレクトリ構成などをまとめ、**真似しやすい形**にする。
- セットアップ手順をステップ形式で書き、「ここだけは注意」のような**罠ポイント**も書く。

**チェックポイント**

- 「技術スタック」「セットアップ手順」「注意点」の3点セットが揃っているか？
- 単なる貼り付けではなく、「なぜこの設定が必要か」が1行で説明されているか？

## 推奨記事テンプレート

Qiitaでポエム〜実践ノウハウ系の記事を書くときの、汎用テンプレート。
必要に応じて削ったり入れ替えたりして使う。

```markdown
---
title: タイトル
tags: [タグ1, タグ2, ...]
---

## 想定読者

- （属性×状態）
- （具体的な悩み）

## この記事でわかること

- 箇条書きで3〜5個

---

## はじめに：背景と気づき

- 自分の原体験・違和感・焦り
- なぜこの記事を書こうと思ったか

## ロールモデル / ゴール像

- 「こうなりたい」人・状態の例
- それを構成する要素のざっくりした一覧

## コアとなるフレームワーク / 方程式

- 例: 市場価値 = 希少性 × 需要
- 要素分解したツリー・図・箇条書き
- なぜその分解が役に立つか

## 各要素の解説

- 要素1：◯◯
  - 何か / なぜ大事か
  - 自分の体験・エピソード
- 要素2：◯◯
- 要素3：◯◯

## 今日からできる具体的な一歩

- Step1（所要時間 3時間）
- Step2（所要時間 30分）
- Step3（所要時間 5分）

## 使ってみた感想 / Before-After

- Before: どんな状態だったか
- After: どう変わったか（時間・ストレス・成果など）

## まとめ

- 方程式・フレームの再掲
- 想定読者へのラストメッセージ
```

## コツのチェックリスト

記事を書く前・書いた後に、このチェックリストを使う。
最低でも「★」付きの項目は満たすことを目指す。

### 読者・ゴール設計

- [ ] ★ 想定読者が「属性×状態」で1文に書けている（例: 「実務3年目でキャリアの次の一歩に迷っているWebエンジニア」）
- [ ] ★ 読者が記事を読み終えた後の状態（できるようになっていてほしいこと）が1〜2文で書けている
- [ ] 「この記事でわかること」が3〜5個の箇条書きで具体的に書かれている

### ストーリーテリング

- [ ] ★ 冒頭に自分の感情（焦り・違和感・モヤモヤ）が1〜2文入っている
- [ ] 「できる人の成功談」ではなく、「目指している途中の思考ログ」というスタンスが伝わる一文がある
- [ ] ロールモデルやゴール像の具体例が1つ以上入っている

### 構造化・フレームワーク

- [ ] ★ 記事全体を貫く「方程式」「フレーム」「図」が1つ定義されている
- [ ] 長い文章が続きすぎず、途中に図・ツリー・コードブロック・表などの構造化されたブロックが挟まっている
- [ ] 要素分解（◯◯の4要素、3ステップなど）が1つ以上含まれている

### 行動可能性・再現性

- [ ] ★ 「今日からできる具体的な一歩」が1セクションとして存在する
- [ ] 各ステップにおおよその所要時間が書かれている
- [ ] セットアップ手順や技術スタックが一覧化されており、読者が真似しやすい

### 実体験・Before/After

- [ ] 自分のBefore/Afterが時間や感情で描写されている（例: 「以前は3〜4時間かかっていたが、今は1時間」）
- [ ] 「予想以上に◯◯だった」「正直、△△だった」といった率直な感想が含まれている
- [ ] 実際に使いながら改善したエピソードが1つ以上ある

### メタ視点・締め

- [ ] 「この記事自体も◯◯で書いている」などのメタな一文がある
- [ ] 最後に、読者に対して「こういう人に届いてほしい」「もし同じ悩みがあれば〜」などのメッセージがある

## 使い方の例

### 新しく記事を書くとき

1. 想定読者と「この記事でわかること」をまず2〜3分で書き出す。
2. 上の「推奨記事テンプレート」をコピペして、今回の記事用にざっくり埋める。
3. 特に伝えたいメッセージを1〜2文で書き、そのメッセージを支えるフレーム/方程式を1つ考える。
4. 本文を書き終えたら、「コツのチェックリスト」の★項目だけでも満たせているか確認する。

### すでにある草稿をブラッシュアップするとき

1. まず草稿をざっと読み、「どの読者に向けて書いたのか」「読み終えた後どうなってほしいか」を改めて言語化する。
2. チェックリストを上から順に見て、欠けているセクションを追記する：
   - 「想定読者」「この記事でわかること」がなければ追加
   - 原体験・感情が弱ければ、冒頭に1〜2段落追加
   - 方程式・フレームがなければ、1つ簡単な式やツリーを考える
3. 最後に「今日からできる具体的な一歩」のセクションを追加し、所要時間を添える。
