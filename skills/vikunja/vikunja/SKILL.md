# Vikunja

MCP `user-vikunja`. No `gh`. Terms: [glossary.md](glossary.md).

New project, or its kanban not set up yet: read [setup.md](setup.md). Once per project.

Worktree task, or target git is not this workspace: read [worktree.md](worktree.md) before edits. Do not run setup.

Use IDs recorded in `AGENTS.md` (project, kanban view, buckets, category labels) directly. Only call `projects_read`, `buckets_list`, or `labels_list` when an ID is missing from `AGENTS.md`.

Do not fetch the full tool catalog. Only inspect schemas for unlisted tools with a single `toolName`, or `find_action` `{action}` (no `resource`), then `do_action`.

## Tool arguments & minimal `fields`

- `projects_read`: `{id, fields: ["id", "views.id", "views.view_kind"]}`
- `tasks_list`: `{filter, expand: ["buckets"], fields: ["id", "identifier", "title", "done", "buckets.id", "buckets.title", "labels.id", "labels.title"]}`
- `tasks_read`: `{task, format: "markdown", expand: ["buckets"], fields: ["id", "identifier", "title", "description", "done", "buckets.id", "buckets.title", "labels.id", "labels.title"]}`
- `tasks_create`: `{project, title, description, format: "markdown"}`
- `tasks_update`: `{task, ...}` (`format: "markdown"` when updating `description`)
- `task_comments_create`: `{task, comment, format: "markdown"}`
- `task_comments_list`: `{task, format: "markdown", fields: ["id", "comment", "author.username", "created"]}`
- `labels_list`: `{fields: ["id", "title"]}`
- `do_action` `task_labels_create`: `{task, label_id}` (fails if already attached)
- `do_action` `task_labels_delete`: `{task, label}`
- `do_action` `task_bucket_update`: `{project, view, bucket, task_id}`
- `do_action` `buckets_list`: `{project, view, fields: ["id", "title"]}`

UI ticket `PROJ-N`. Server assigns N and numeric `id`. Resolve `PROJ-N` via `tasks_list` matching `identifier`. `tasks_create` cannot set either number.

`format: "markdown"` on project, task, and comment read/write. Blank line between blocks. One newline becomes a space.

Triage comment starts with `> *This was generated by AI during triage.*` then a blank line.

## Labels (category only)

Labels are per user. Attach exactly one category label per task: `bug` (broken) or `enhancement` (new or improved). Never create or attach state labels. If a category label ID is not in `AGENTS.md`, check `labels_list` before `labels_create`.

## State (kanban buckets only)

State is the task's kanban bucket, in order:

- `needs-triage`: maintainer must evaluate (default bucket on create)
- `needs-info`: waiting on the reporter
- `ready-for-agent`: an AFK agent can do it
- `ready-for-human`: a human must do it
- `wontfix`: will not do it (leave `done: false`)
- `Done`: finished work (`done_bucket_id`)

Create order: `tasks_create`, one category `task_labels_create`, and (if initial state is not `needs-triage`) `task_bucket_update` to the target state bucket.

On state change: `task_bucket_update` `{project, view, bucket, task_id}` into the target bucket.

Finished work: `tasks_update` `{task, done: true}`. The card moves to `Done` automatically. Do not use `wontfix` for finished work. Moving out of `Done` clears `done`. A repeating task marked `done` reopens onto `needs-triage`.

No relation API. Blocking goes in the description. Blockers first.

```
## Blocked by

- MEMO-1 (id 8) title
```

None: `None (can start immediately)`.

Named project only. Never Inbox or My Open Tasks.
