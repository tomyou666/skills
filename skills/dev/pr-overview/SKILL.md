# PR Overview

ステージ済み差分から、技術に詳しくないレビュアー向けの PR/MR 本文をチャットに出す。作成・push・MR オープンはしない。

## いつ使うか

`/pr-overview` で明示されたときだけ。本文を書く・直す依頼でも、このスキルが添付または指名されていなければ使わない。

## 進行

1. git を読む。推測しない。
   - 優先順: ステージ済み → 未ステージの差分 → ブランチの `main`/`master` からのコミット範囲
2. ユーザーがタイトルを出していればそれを使う。差分が広くてもタイトルは変えない。足りない範囲は概要で補う。
3. 下記テンプレートだけをチャットに出す。
4. ブランチ作成・commit・push・GitLab/GitHub への作成は、ユーザーが明示したときだけ。このスキル単体ではやらない。

## 出力（この見出しだけ）

```markdown
**タイトル**

[タイトル]

**本文**

## 概要

[困っていたことと、今回やったことの要約。2〜4文]

## 変更内容

- [利用者・運用者に見える変化]
- [利用者・運用者に見える変化]

## 確認したこと

- [x] [手元または画面で確認したこと]
```

## 書き方

- 日本語。概要レベル。クラス名・メソッド名・ファイル一覧・テストクラス名は書かない。
- 「なぜ」は動作が変わる理由だけ。実装の手順や内部構造は書かない。
- タイトルが差分より狭いときは、概要の2文目で実際の範囲を平易に補う。
- 変更内容は利用者が観測できる結果で書く。安全装置があるなら「誤って他アプリを終了しない」のように書く。
- 確認したことは、成功・失敗・副作用の3点を優先し、チェック済みの TODO 形式（`- [x]`）で書く。

## 例

入力: タイトル「マクロ実行失敗時にエクセルプロセスを削除」。差分は失敗時キルに加え、時間切れ・残留回収・作業ファイルの再削除。

出力:

```markdown
**タイトル**

マクロ実行失敗時にエクセルプロセスを削除

**本文**

## 概要

マクロ実行が失敗したり、時間切れになったりしたあと、Excel が裏側で残ることがあります。
残った Excel が次の処理やファイル削除を邪魔するため、処理の終了時に Excel を確実に終了するようにしました。

失敗時だけでなく、時間切れ・処理の中断・正常終了後に Excel が残っていた場合も対象です。

## 変更内容

- マクロ処理の終了時に、今回起動した Excel を終了する
- 次のジョブ開始前に、以前から残っている Excel があれば回収する
- 作業用にコピーしたファイルがすぐ消せない場合は、少し待ってから再試行する
- Excel 以外のアプリは誤って終了しない

## 確認したこと

- [x] マクロが失敗・時間切れになったあと、Excel が残っていないこと
- [x] 通常の成功時も、これまで通り結果が返ること
- [x] 手元で開いている Excel を誤って閉じないこと
```
