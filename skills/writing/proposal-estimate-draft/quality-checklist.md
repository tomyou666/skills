# 保存前チェックリスト

## 承認

- [ ] 必須情報と不足情報を確認した
- [ ] 要件・前提・人日・出力先について最終承認を得た
- [ ] 同名ファイルがある場合は上書き承認を得た

## 事実と整合性

- [ ] 推測した顧客情報、数値、固有名詞がない
- [ ] 根拠情報をMarkdownコメントで残した
- [ ] 未回答のプレースホルダーがない
- [ ] 課題、要望、提案機能が内部的に対応している
- [ ] 提案書と見積明細で、名称、範囲、前提、対象外が一致している

## 提案書

- [ ] 冒頭情報ブロックがある
- [ ] 課題と要望が簡潔な箇条書きである
- [ ] システム概要が2〜3文と主要機能の箇条書きである
- [ ] ITに詳しくない読者でも読める粒度である
- [ ] 実装手順、設定値、内部APIの挙動を提案書に書いていない
- [ ] 試算専用の細かい性能数値やクラウド料金リンクを提案書に置いていない
- [ ] サービス名を出す場合は役割とセットで短く説明している
- [ ] Mermaid図が `flowchart LR` である
- [ ] 図に利用者、提案システム境界、外部システム、データ流がある
- [ ] 詳細に機能、外部連携、データ、セキュリティ、運用、前提条件、対象外がある
- [ ] スケジュールが確認済みの体制、並行作業、依存関係と矛盾しない
- [ ] エグゼクティブサマリー、効果・KPI、次のアクションを無断で追加していない

## 見積り

- [ ] `## 技術前提・実装方針` がある
- [ ] 提案書から外した実装詳細・設定値・試算条件が見積明細側にある
- [ ] 1人日＝8時間、0.5人日単位である
- [ ] 列が `No.｜機能｜設計｜実装｜テスト｜その他（要件定義、導入、バッファ）｜小計｜費用｜備考` である
- [ ] 行が機能単位で、設計・実装・テストが同じ機能行に揃っている
- [ ] 横断作業（要件定義、結合・総合試験、受入支援、導入）が別行である
- [ ] 負荷試験が独立行になっていない
- [ ] バッファと予備工数を無断で加えていない
- [ ] 0人日のセルが空欄である
- [ ] 各行の `小計` が設計 + 実装 + テスト + その他と一致する
- [ ] 各機能行の備考に短い根拠がある
- [ ] 見積明細の費用が空欄である
- [ ] 見積明細の人日合計と、提案書の工程別人日合計が一致する
- [ ] 提案書の要件定義が、機能名が要件定義の行の `その他` と一致する
- [ ] 提案書の設計が設計列合計、実装が実装列合計、試験がテスト列合計と一致する
- [ ] 提案書の導入が、機能名が導入の行の `その他` と一致する
- [ ] バッファを計上した場合のみ、提案書に予備行がある
- [ ] 各工程のMock金額が `工程人日 × 50,000円` と一致する
- [ ] Mock金額の合計が `合計人日 × 50,000円` と一致する
- [ ] Mock金額が `¥1,500,000（税別・Mock）` 形式である
- [ ] 人件費以外の既知費用を別枠、未確定費用を `別途` とした
- [ ] クラウド利用料の試算額やCalculatorリンクがある場合、提案書ではなく見積明細にある
- [ ] Mock、税別、再見積り条件を明記した

## Obsidian・ファイル

- [ ] 保存先が `02-Projects/<顧客名>/<案件名>/` である
- [ ] ファイル名が命名規則に一致する
- [ ] フロントマターは `title` と `created` だけである
- [ ] ノートタイトル用の `#` 見出しがない
- [ ] メインセクションが `##`、サブセクションが `###` である
- [ ] 提案書と見積明細がObsidian内部リンクで相互参照されている
- [ ] 固定タグと案件別タグがノート末尾にある
- [ ] 改行コードがLFである
