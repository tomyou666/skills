# 解説を書く

読者が、隣の分野の知識のうえで、そのテーマの全体と各部分の位置を追えるように書く。

## いつ使うか

- わかりやすい解説を新規に書くとき
- 既存の解説をこの型で書き直すとき

## 書く前

1. 依頼が2本以上のテーマに割れるときだけ、どれを書くか聞く。読者は聞かない。
2. 依頼に読者が書いてあれば、その読者に合わせる。なければ、隣分野の基礎は既知とする。開発や道具の話ならファイルとコマンド、数学なら高校までの計算は説明しない。
3. 依頼にない論点は足さない。

## 書き方

1. 冒頭に、対象の全体像を1段落書く。目次は置かない。
2. そのあと節を並べる。節の切り方と見出しの文言はテーマに合わせる。固定の章題は使わない。
3. 各節はこの順にする。
   - **先頭文**。平易に書いて定義と矛盾しないなら平易に書く。平易にすると偽になるなら、正確な文を先に書き、直後に平易な言い換えを続ける。どの箇所でそうするかは内容で判断する。
   - **具体をひとつ**。
   - **全体のどこか**を1文。その具体が全体のどの位置かを書く。
4. 次は内容に合わせて決める。例を独立した節にするか、そのテーマの新しい語の出し方、たとえ、長さ、式・短いコード・手順をどこまで入れるか。

## 出し方

- チャットに Markdown で出す。
- ファイルは頼まれたときだけ書く。保存先の指定がなければ聞く。

## 例

平易な先頭文で足りるとき:

```markdown
## plan

- plan は、いまの実物と書いた設定との差を、まだ変えずに一覧する操作。
- `terraform plan` を実行すると、追加するサーバが1台と出る。反映はしない。
- 全体では、設定を書いたあとに行い、apply の前に置く。
```

平易にすると偽になるとき:

```markdown
## 固有値

- 正方行列 A、スカラー λ、ゼロでないベクトル x が Ax = λx を満たすとき、λ を A の固有値という。平たく言うと、そのベクトルの方向だけは、行列をかけても向きが変わらず、長さが λ 倍になる。
- 行列 [[2, 0], [0, 3]] では、横方向は2倍、縦方向は3倍になり、向きは変わらない。2 と 3 が固有値。
- 全体では、行列が空間をどう変形するかのうち、向きが保存される方向だけを取り出したもの。
```
