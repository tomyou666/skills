エージェントは案件ごとにこの構造で TODO ノートを作る。チェック結果は案件の事実で埋める。空欄のまま「完了」にしない。

## 締結前TODO

| 項目 | 内容 |
|---|---|
| 元請 | |
| 案件 | |
| 類型 | 請負A / 準委任B |
| 商流 | エンド → 元請 → 自分（受注者） |
| 再委託 | なし（原則） |

### ブロッカー

先に判断する。一つでも未解消なら、見積に「発注可」と書かない。

- [ ] 類型が元請の提示どおりに確定している（こちらから変更しない）
- [ ] 仕様確定者と検収権者が特定できている
- [ ] 請負Aなのに仕様未確定のまま完成義務を負っていない
- [ ] 準委任Bなのに成果物完成を約束する文言が元請提示に混ざっていない（混ざっている場合は見積側で準委任文言に揃える。類型交渉はしない）
- [ ] 開始条件（資料・環境・アカウント・意思決定者）が書ける
- [ ] 権利のないもの（他人のコード、アカウント、ライセンス）を成果物に混ぜない方針が取れている
- [ ] 再委託する場合、その旨を見積前提に書いた

### 書類

- [ ] 正式見積（または明示した概算）を出した
- [ ] 見積の前提・検収・対象外が本文にある
- [ ] 注文書が届いた
- [ ] 注文書と見積の差分を確認した（品名、金額、納期、支払、検収、対象範囲）
- [ ] 差分なし → 注文請書を出した
- [ ] 差分あり → 請書を出さず差戻した

### 下請法・支払（助言しない）

自分は個人事業主として下請事業者側になりうる。次はチェックのみ。判断に迷えば「専門家に確認」と書く。

- [ ] 注文書（またはこれに代わる書面）に、業務内容、金額、支払期日、給付内容が書かれている
- [ ] 支払は検収月の翌月末で、給付の受領日から起算して60日を超えないか確認した（超えそうなら専門家確認）
- [ ] 検収を理由に支払期日を実質無期限にしていない（10営業日のみなし確認がある）
- [ ] 下請法の禁止事項（受領拒否、支払遅延、不当な返品・減額、買いたたき等）に該当しそうな条項が注文書にないか眺めた

### サンドイッチ

- [ ] 完成義務・提出先は元請までと見積に書いた
- [ ] エンド検収待ちかどうかが検収条件に落ちている
- [ ] エンド起因の変更が追加見積になると書いた
- [ ] 依存遅延が納期延伸になると書いた

### 知財・秘密

- [ ] 成果物の権利移転は検収合格かつ支払完了後、元請へ、と書いた
- [ ] エンドへの直接譲渡を書いていない
- [ ] 既存資産・ノウハウ留保は書いていない（書かない方針）
- [ ] 秘密情報の受領範囲が過剰でない（書けない場合は「別途、元請の秘密保持に従う」程度）
