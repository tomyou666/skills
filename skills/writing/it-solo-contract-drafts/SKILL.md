# IT自営業 準委任・請負 締結ドラフト

ユーザーがこのスキル名を明示したときだけ実行する。

## 立場（固定）

- 商流は `エンドユーザ → 元請 → 自分`。自分は受注者。
- 自分が出すのは見積書と注文請書。注文書は元請が出す。注文書ドラフトは作らない。
- 再委託は原則しない。する場合は見積前提に必ず書く。黙って再委託しない。
- 契約類型（請負A / 準委任B）は元請が決める。類型変更の交渉文は出さない。
- 下請法の法的助言はしない。チェックと専門家確認フラグだけ出す。

## 使わない

- `proposal-estimate-draft`（提案書・人日の概算見積明細）
- 基本契約書・個別契約書の全文
- 下向き注文書、下の名義での代筆見積・請書

概算見積明細が既にある場合は金額・範囲の入力として読んでよい。ただし本スキルの見積は締結用であり、人日表の転記では終わらせない。

## 出力

保存先:

- 案件が決まっていれば `02-Projects/<元請または顧客>/<案件>/`
- 未定なら `00-Inbox/`

ファイル:

- `<元請>-<案件>-締結TODO.md`
- `<元請>-<案件>-見積書.md`（概算のときは `-概算見積書.md`）
- `<元請>-<案件>-注文請書.md`（注文書と相違があるときは請書を承諾文にせず、同名ではなく差分メモにする。後述）

Windowsで使えない文字 `\ / : * ? " < > |` はフォルダ名・ファイル名から除去または全角化する。

同名ファイルがある場合は上書き前に確認する。改行はLF。フロントマターは `title` と `created` のみ。ノートタイトル用 `#` は使わない。タグは末尾。

## 進行フロー

### 1. 類型と入力を確定する

不足は推測で埋めない。まとめて聞く。

必須:

- 元請の正式名称、案件名
- 類型: 請負A / 準委任B（元請が決めたもの）
- 正式見積か概算か（既定は正式）
- 件名、期間または納期
- 金額（Aは成果物一式、Bは月額税抜）
- Bは月間基準時間（未指定なら例として160時間を提案し、確定してから書く）
- 成果物（A）または業務範囲（B）
- 仕様の確定者（エンド / 元請）、検収権者（元請で閉じるか、エンド検収待ちか）
- 開始条件・依存（資料、環境、アカウント、意思決定）

発行者（`{{屋号}}` 等）はユーザーがこの会話で出した場合だけ埋める。出なければプレースホルダのまま残す。

### 2. TODOを先に埋める

[todo-template.md](todo-template.md) を使い、ブロッカーを見積本文より先に列挙する。

ブロッカーがあるまま見積を「発注してよい」とは書かない。ドラフト自体は出してよい。

### 3. 見積を書く

[estimate-template.md](estimate-template.md) の該当類型だけ使う。AとBを混ぜない。

必須で本文に書く:

1. 成果物の定義（A）または業務の範囲（B）。対象外を併記する
2. 検収条件（期間、みなし、指摘の粒度）
3. 前提・依存（開始条件）
4. 再委託（原則なし）
5. 変更管理
6. 支払条件（検収月の翌月末）
7. 契約不適合（類型どおり）
8. サンドイッチ5項（下記）

サンドイッチ5項（毎回）:

1. 仕様の確定者は誰か
2. 検収権者は誰か。元請検収で閉じるか、エンド検収待ちか
3. 環境・データ・アカウント・意思決定の遅延は納期の自動延伸とする
4. 元請がエンドから受けた変更を流す場合は変更管理（追加見積）とする
5. 成果物の提出先は元請。エンドへの直接納品・直接の完成義務は負わない

### 4. 請書を書く

[order-ack-template.md](order-ack-template.md) を使う。

- 注文書未着: 転記欄は空。見積前提の要約は埋める。見出しに「注文書未着の下書き」と付ける
- 注文書あり・見積と一致: 品名・金額・納期を転記し、前提を要約再掲する。「見積番号XXのとおり」の一文だけは禁止
- 注文書あり・相違あり: 注文請書として承諾しない。`<元請>-<案件>-注文書差分.md` に差分リストと差戻し文だけ出す

### 5. 保存前検査

- 請負AにBの精算文（6,500円、15分、1.5割増、交通費実費）が入っていない
- 準委任Bに「完成」「完成義務」「仕様適合の保証」が入っていない
- Bの精算4項目がユーザー原文のままである（言い換えない）
- 知財に既存資産・汎用部品・ノウハウの留保がない
- 有効期限は発行日から30日、税は外税10%で税抜・消費税・税込の3行
- 概算なら「本見積ではない。発注根拠にしない」が先頭にある
- 請書が「見積のとおり」だけで終わっていない

## 類型の書き分け

| 項目 | 請負A | 準委任B |
|------|-------|---------|
| 見出しの類型 | 請負 | 準委任（業務委託） |
| 金額 | 成果物一式＋内訳。人日だけにしない | 月額＋基準時間。完成の対価に見せない |
| 検収 | 引渡後10営業日。沈黙は合格 | 報告受領後10営業日。沈黙は確認済み。実施報告の確認であり仕様合格ではない |
| 契約不適合 | 検収合格後6ヶ月。仕様適合のみ。目的適合・エンド追加要求は対象外 | 付けない。善管注意の範囲のやり直しのみ |
| 知財 | 検収合格かつ支払完了後に当該成果物は元請へ。エンドへ直接譲渡・直接ライセンスしない | 同じ |
| 修正 | 検収指摘は具体的不適合のみ | 「もうちょっと」は範囲外 |
| 精算 | 入れない | 原文ブロックのみ |
| 働き方 | リモート前提。常駐・出張は別見積 | リモート前提。週次報告。元請・エンド従業員の直接指示は範囲変更 |

Bの精算は次をこの字句のまま使う。順序も変えない。

稼働時間精算： 月間基準時間を超過、または未達（控除）となった場合は、1時間あたり 6,500円 を加算・減算いたします。
精算単位： 稼働時間の算出は 15分単位 とします。
時間外手当： 休日および深夜業務（22:00〜翌5:00）が発生した場合は、稼働時間精算の1.5割増を別途請求いたします。
交通費： 業務に伴う移動が発生した場合は、実費を別途精算させていただきます。

## プレースホルダ

発行者は次の項目名で固定する。値が無い欄は `{{項目名}}` のまま残す。

`{{屋号}}` `{{氏名}}` `{{住所}}` `{{電話}}` `{{メール}}` `{{インボイス登録番号}}` `{{振込先}}`

未登録ならインボイス欄は「登録なし」と書いてよい（ユーザーがそう言った場合のみ）。

## タグ

- 見積: `#見積書 #プロジェクト` と `#請負` または `#準委任`
- 請書: `#注文請書 #プロジェクト` と類型タグ
- TODO: `#契約 #プロジェクト` と類型タグ
- 概算見積には `#概算見積り` を足す
